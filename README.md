# Календарь звонков

[![hexlet-check](https://github.com/skaffman41/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/skaffman41/ai-for-developers-project-386/actions)

Разработайте совместно с ИИ сервис для бронирования календаря

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Пользовательские сценарии

В сервисе один заранее заданный владелец календаря. Гости записываются на встречи без регистрации.

### Владелец календаря

1. Открывает отдельный раздел управления без входа и проверки прав.
2. Создаёт тип встречи: указывает обязательные название и длительность в целых положительных минутах. Описание необязательно.
3. Просматривает типы встреч и список бронирований: тип встречи, дату, время, имя и email гостя.

### Гость

1. Выбирает тип встречи.
2. Выбирает дату и свободный слот в календаре.
3. Вводит обязательные имя и email и подтверждает бронирование.
4. Получает подтверждение на экране с типом встречи, датой, временем и часовым поясом. Письма не отправляются.

Если свободных слотов нет, гость выбирает другую дату или тип встречи.

Если выбранный интервал успели забронировать, гость видит алерт «Слот уже занят». После закрытия алерта список слотов обновляется, а введённые имя и email сохраняются для повторной попытки. При одновременных попытках подтверждается только одна бронь.

### Правила доступности

- Все даты и время рассчитываются и отображаются в часовом поясе `Europe/Moscow`.
- Календарь показывает сегодня и следующие 13 календарных дней. Рабочее время — понедельник–пятница, 09:00–18:00; выходные недоступны.
- Допустимые начала встреч идут с шагом 30 минут от 09:00. Длительность фиксирована у типа встречи и не обязана быть кратной 30 минутам.
- При проверке доступности учитывается полный интервал встречи: начало строго позже текущего времени, окончание не позже 18:00, пересечений с существующими бронированиями нет.
- Занятость общая для всех типов встреч. Любое пересечение запрещено, но следующая встреча может начинаться сразу после окончания предыдущей.

В первую версию не входят редактирование и удаление типов встреч, отмена и перенос бронирований, авторизация, интеграции с внешними календарями и уведомления.

## Стек

- Frontend: React 19.3.1, TypeScript 6.0.3, Vite 8.3.6.
- Backend: Fastify 5.12.8, TypeScript, ESM; Node запускает TypeScript в разработке, после сборки — JavaScript.
- Проверки: Vitest 5.1.0, Playwright 1.65.0 (Chromium), ESLint 10.14.0, typescript-eslint 8.72.1, Prettier 3.9.10.
- Приватные npm workspaces `contract`, `frontend` и `backend`, один корневой `package-lock.json`.
- mise 2026.11.3 управляет Node 24.22.2, встроенным npm 11.19.1, hk 2.11.1 и GitHub CLI 2.103.3. Точные версии JS-зависимостей указаны в manifests.

## Установка

Поддерживаемые окружения: macOS arm64 и Linux x64. Нужны Git и curl.
Установите точную версию mise по [официальной инструкции](https://mise.jdx.dev/installing-mise.html):

```bash
curl --fail --silent --show-error --location https://mise.run | MISE_VERSION=v2026.11.3 sh
export PATH="$HOME/.local/bin:$PATH"
mise --version
```

Добавьте `~/.local/bin` в `PATH` своего shell для следующих сеансов. Подготовьте проект из корня:

```bash
git clone https://github.com/skaffman41/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise trust
mise install --locked
mise run setup
mise run browser:install
```

На Linux используйте `mise run browser:install -- --with-deps`: Playwright установит
также системные библиотеки Chromium (для этого могут понадобиться права sudo).
Команда загружает браузер, соответствующий закреплённой версии Playwright; повторите её
после обновления Playwright. [Официальный registry](https://registry.npmjs.org/@playwright/test/1.65.0)
указывает Node `>=20`, совместимый с Node 24 проекта. Подготовка браузера следует
[инструкции Playwright](https://playwright.dev/docs/browsers#install-browsers).

`mise.lock` фиксирует Node, hk и gh с контрольными суммами для обеих платформ.
`setup` проверяет точные версии mise, Node и npm, выполняет `npm ci`, затем `hooks:install`.
Хук hk устанавливается только для текущего клона через `hk install --mise`; глобальная Git-конфигурация не меняется.
Отдельный Pkl CLI не нужен: hk использует встроенный evaluator.
Отдельный сервер БД, глобальные JS-пакеты, ключи и внешние сервисы для запуска не нужны.
SQLite встроен в Node; постоянный файл нужно явно подготовить по инструкции ниже.
Для первой установки инструментов, npm-зависимостей и Chromium нужен доступ к источникам загрузки.

## Использование

Все команды выполняются из корня:

Сначала выберите постоянный локальный каталог вне временных файлов, зависимостей и
результатов сборки. Файл и соседние SQLite journals должны оставаться на том же
исправном диске при перезапуске и пересборке. Пример для локальной разработки:

```bash
mkdir -p "$HOME/.local/share/call-calendar"
export DATABASE_PATH="$HOME/.local/share/call-calendar/calendar.sqlite"
mise run db:prepare
mise run dev
```

`db:prepare` один раз создаёт **пустую** БД без демонстрационных данных; существующий
файл не заменяет. При следующих запусках достаточно задать тот же абсолютный
`DATABASE_PATH` и выполнить `mise run dev`. Каталог должен существовать и допускать
запись файла и rollback journal. Не используйте сетевой диск, `/tmp`, `node_modules`
или `dist`; тесты используют свои временные файлы, а данные разработчика не трогают.

Обычный запуск открывает только существующую БД (`mode=rw`), проверяет приложение,
версию/структуру схемы и целостность. Отсутствующий, недоступный, повреждённый или
чужой файл останавливает backend до HTTP. Подмены пустым файлом или памятью нет.
Подготовка схемы/версии — одна транзакция. Сейчас поддерживается версия 1; чужие и
будущие версии отклоняются без сброса. Сохраняются `journal_mode=DELETE`,
`synchronous=EXTRA`, `foreign_keys=ON`, ожидание блокировки до 5000 мс; на macOS —
`fullfsync=ON`. Гарантия сохранности предполагает исправные диск, файловую систему
и синхронизацию ОС; автоматическое резервное копирование не входит в эту версию.

Откройте http://127.0.0.1:5173: главная объясняет запись на встречу без регистрации.
Ссылка «Записаться на встречу» открывает `/booking` с реальным списком типов встреч:
название, длительность, описание и устойчивое обозначение. Новые типы идут первыми;
на пустой БД доступно обновление списка. Загрузка, ошибка и повтор показаны отдельно.
Адрес работает напрямую, после обновления и с обычной историей браузера. Создание
типов и дальнейшие шаги записи добавляются следующими срезами согласованного плана.
Backend доступен на http://127.0.0.1:3000. Проверка состояния:

```bash
curl --fail --silent --show-error http://127.0.0.1:3000/health
# {"status":"ok"}
```

Ctrl+C останавливает обе части и освобождает порты. Ошибка запуска одной части завершает общий запуск.
Занятый выбранный порт вызывает ошибку; автоматического перехода на другой порт нет.

| Команда                          | Результат                                                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `mise run dev:frontend`          | Только frontend, http://127.0.0.1:5173, обновление при изменении исходников.                                                               |
| `mise run dev:backend`           | Только backend, http://127.0.0.1:3000, Node watch перезапускает сервер при изменениях.                                                     |
| `mise run typecheck`             | Строгая проверка типов обеих частей и конфигурации, включая вспомогательные скрипты.                                                       |
| `mise run lint`                  | ESLint для JavaScript/TypeScript обеих частей, тестов и конфигурации; предупреждения считаются ошибкой.                                    |
| `mise run format:check`          | Проверка форматирования Prettier без изменения файлов.                                                                                     |
| `mise run format`                | Исправление форматирования Prettier; результаты сборки, зависимости, lockfiles и workflow Hexlet исключены.                                |
| `mise run check`                 | Проверка версий, линтера, форматирования, типов, сборка, HTTP smoke, Playwright и `hk validate`. Сборка выполняется один раз до тестов.    |
| `mise run build`                 | Сборки в `contract/dist`, `frontend/dist` и `backend/dist`.                                                                                |
| `mise run test`                  | Сборка обеих частей и HTTP smoke и проверки контракта/хранения в Vitest без watch; серверы запускаются и останавливаются автоматически.    |
| `mise run browser:install`       | Подготовка закреплённого Chromium; на Linux добавьте `-- --with-deps`.                                                                     |
| `mise run test:browser`          | Сборка и браузерные сценарии гостя в Chromium на собственном frontend preview и отдельном реальном backend/файле SQLite для каждого теста. |
| `mise run start:backend`         | Запуск `backend/dist/server.js` после сборки.                                                                                              |
| `mise run preview:frontend`      | Просмотр сборки на http://127.0.0.1:4173 после сборки.                                                                                     |
| `mise run env:check`             | Проверка точных версий mise, Node и npm.                                                                                                   |
| `mise run hooks:install`         | Повторная установка локального pre-commit через mise.                                                                                      |
| `mise exec -- hk validate`       | Проверка конфигурации hk без запуска линтера и форматирования.                                                                             |
| `mise exec -- hk run pre-commit` | Ручной запуск pre-commit без создания коммита.                                                                                             |

Общий контракт — [OpenAPI 3.1](contract/openapi.json), производная документация —
[API.generated.md](contract/API.generated.md). Генератор `@hey-api/openapi-ts` 0.99.0
выпускает модели, схемы, SDK и типы ручных Fastify-обработчиков; детерминированный
адаптер дополняет их реестром операций и документацией. `mise run api:generate`
обновляет производные файлы; вручную их не меняют. `mise run api:check` офлайн
валидирует OpenAPI/JSON Schema и повторяет генерацию во временный каталог, сравнивая
весь набор файлов и значения выпущенных схем с источником. Эта проверка и
компиляция всех трёх частей входят в `check`.
Ajv2020 проверяет запросы и ответы без автоматического изменения значений; клиент
проверяет также статус и тип содержимого. Backend не импортирует браузерный SDK.

Владелец открывает `/owner` напрямую или по ссылке «Владельцу календаря» в шапке.
Созданный тип сохраняется в SQLite и появляется в `/booking`. До отправки форма
сохраняет UUID и исходные данные в `sessionStorage` вкладки. При неизвестном исходе
поля заблокированы; «Повторить создание» и обновление вкладки используют прежнюю
отправку без второго типа. Если `sessionStorage` недоступен, POST не выполняется.
Типы пока нельзя изменять или удалять. Операции не требуют входа.

Frontend использует относительный `/api`; Vite dev/preview проксирует его на
`http://127.0.0.1:3000`. Для другого backend задайте `API_PROXY_TARGET` при запуске
frontend. При отдельном размещении собранной статики настройте тот же `/api` на
reverse proxy.

Для backend можно задать `HOST` (по умолчанию `127.0.0.1`) и `PORT` (по умолчанию `3000`):

```bash
HOST=127.0.0.1 PORT=3100 mise run dev:backend
```

`PORT=0` выбирает свободный порт; фактический адрес выводится в журнал.
Для Vite порт можно задать через аргумент: `mise run dev:frontend -- --port 5174`.
`preview:frontend` предназначен для локального просмотра сборки.
Изменения зависимостей выполняются через `mise exec -- npm ...`; повторная установка — `mise run setup`.
HTTP smoke проверяет `/health`, HTML frontend и его JS-ресурс на собственных свободных loopback-портах.
Готовность ограничена 30 секундами, запрос — 5 секундами; при ошибке выводятся адрес и журналы процессов.
После успеха и ошибки серверы и соединения закрываются. Проверка не требует вручную запущенных серверов
и не проверяет отрисовку React в браузере.

Playwright отдельно выполняет сценарии гостя через роли и доступные названия: содержимое
главной, переход к записи, прямое открытие и обновление `/booking`, возврат и историю браузера.
Он обслуживает готовую сборку через Vite preview на `http://127.0.0.1:4183`;
порт должен быть свободен, уже запущенный сервер не переиспользуется. Backend запускается на `127.0.0.1:3183` с отдельной временной SQLite для каждого
сценария. Preview, backend и браузерные контексты завершаются после успеха и ошибки.
После запуска HTML-отчёт сохраняется в игнорируемом `playwright-report/`;
открыть его можно через `mise exec -- npx playwright show-report`.
При неуспехе trace и скриншот сохраняются в игнорируемом `test-results/`;
trace можно открыть через `mise exec -- npx playwright show-trace <путь-к-trace.zip>`.
В GitHub Actions отчёт и доступная диагностика публикуются в артефакте
`playwright-diagnostics-<run_id>-<run_attempt>` на 14 дней, в том числе после ошибки check.
Это проверка локальной сборки; публичный хостинг также должен отдавать frontend для `/booking` и `/owner`.

`check` возвращает ненулевой код при ошибке любого обязательного шага и не исправляет исходники или lockfiles.
Установленный Git-hook для `check` не нужен: в CI достаточно `mise install --locked`,
`mise exec -- npm ci`, `mise run browser:install -- --with-deps` и `mise run check`;
`setup` и `hooks:install` в CI не требуются. Этот порядок следует
[рекомендациям Playwright для CI](https://playwright.dev/docs/ci).

## Локальные хуки

После `setup` каждый pre-commit вызывает общие `mise run lint` и `mise run format:check`
для всего рабочего дерева, включая незакоммиченные изменения. Нарушение блокирует коммит.
Хук только проверяет: не исправляет файлы, не добавляет их в индекс, не прячет изменения в stash
и не создаёт коммиты. Исправьте код или запустите `mise run format`, проверьте diff и добавьте
нужные изменения в индекс самостоятельно.

`mise run hooks:install` повторно подключает хук текущего клона; флаг `--mise` позволяет Git
найти закреплённые инструменты без активации mise в shell. Сам `mise` должен быть в `PATH`.
Проверить хук без коммита можно командой `mise exec -- hk run pre-commit`.
