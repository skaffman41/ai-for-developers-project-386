# 03: Проверить запуск приложения через настоящий HTTP

**Status:** resolved
**Blocked by:** 02
**What to build:** разработчик запускает одну команду тестов, которая сама собирает приложение, запускает оба процесса, проверяет успешные HTTP-ответы и освобождает ресурсы.
**Спецификация:** [Каркас приложения](../spec.md#testing-decisions).
**Критерии спецификации:** AC-03, AC-05–AC-07; часть AC-08 и AC-09.

Запуск: `$implement 03-smoke-over-http` после завершения зависимостей. Порядок выполнения и границы разрешения — в [development workflow](../../../docs/agents/development-workflow.md).

## Критерии завершения

- [x] Vitest использует Node environment. Есть минимум один smoke-сценарий, который запускает собранные backend и frontend preview дочерними процессами и делает настоящие HTTP-запросы без моков.
- [x] Проверяются HTTP 200 и JSON-контракт /health; у frontend — HTTP 200, HTML Content-Type, корневой элемент React и успешная загрузка указанного JS-ресурса с подходящим Content-Type. SPA HTML вместо JS считается ошибкой.
- [x] Тест использует собственные свободные loopback-порты и не полагается на вручную запущенные серверы. Раннее завершение дочернего процесса обнаруживается; готовность ограничена 30 секундами, запрос — 5 секундами. При ошибке выводятся адрес и вывод процесса.
- [x] После успеха и ошибки дочерние процессы и соединения закрываются. Тест не завершает чужие процессы; повторный запуск проходит без оставшихся занятых портов.
- [x] mise run test из корня сначала собирает обе части, затем однократно запускает Vitest. Нулевой набор тестов не считается успехом. Typecheck охватывает тест и TS-конфигурацию runner.
- [x] Вручную подтверждён ненулевой код тестовой команды при временном нарушении HTTP-контракта или запуске неисправного backend; временные изменения полностью отменены и не коммитятся. Отдельные новые автоматические тесты, browser automation и coverage gates не добавлены.

## Answer

Выполнено **2026-11-07**, macOS arm64. Все критерии задачи 03 подтверждены; статус `resolved`.

Добавлен один `tests/smoke.test.ts`: Vitest в Node environment запускает собранный backend и Vite preview непосредственно через Node, без npm-обёрток и моков. Проверяются точный JSON `{ "status": "ok" }`, HTTP 200 и JSON Content-Type; у frontend — HTTP 200, HTML Content-Type, React root и непустой JS-ресурс из HTML с JavaScript Content-Type. Порты выбираются ОС на `127.0.0.1`, frontend использует `--strictPort`. Smoke не зависит от серверов разработчика.

Общий deadline готовности — 30 секунд, полный HTTP-запрос вместе с телом — не более 5 секунд. Ранние `exit`/`error` дочерних процессов прерывают ожидание через AbortSignal. Ошибка включает URL, PID, stdout/stderr и исходную причину. HTTP использует `agent: false`; таймаут уничтожает запрос. В `finally` оба принадлежащих тесту процесса получают SIGTERM, при необходимости — SIGKILL через 3 секунды; тест ожидает их `close`. Завершение по чужим PID или занятым портам не выполняется.

Новые автоматические тесты и зависимости не добавлены. Исправление сохраняется отдельным коммитом без изменения истории; push не выполняется.
