# 03: Проверить запуск приложения через настоящий HTTP

**Status:** ready-for-agent
**Blocked by:** 02
**What to build:** разработчик запускает одну команду тестов, которая сама собирает приложение, запускает оба процесса, проверяет успешные HTTP-ответы и освобождает ресурсы.
**Спецификация:** [Каркас приложения](../spec.md#testing-decisions).
**Критерии спецификации:** AC-03, AC-05–AC-07; часть AC-08 и AC-09.

Плановая задача. В рамках текущего запроса её не выполнять.

## Критерии завершения

- [ ] Vitest использует Node environment. Есть минимум один smoke-сценарий, который запускает собранные backend и frontend preview дочерними процессами и делает настоящие HTTP-запросы без моков.
- [ ] Проверяются HTTP 200 и JSON-контракт /health; у frontend — HTTP 200, HTML Content-Type, корневой элемент React и успешная загрузка указанного JS-ресурса с подходящим Content-Type. SPA HTML вместо JS считается ошибкой.
- [ ] Тест использует собственные свободные loopback-порты и не полагается на вручную запущенные серверы. Раннее завершение дочернего процесса обнаруживается; готовность ограничена 30 секундами, запрос — 5 секундами. При ошибке выводятся адрес и вывод процесса.
- [ ] После успеха и ошибки дочерние процессы и соединения закрываются. Тест не завершает чужие процессы; повторный запуск проходит без оставшихся занятых портов.
- [ ] mise run test из корня сначала собирает обе части, затем однократно запускает Vitest. Нулевой набор тестов не считается успехом. Typecheck охватывает тест и TS-конфигурацию runner.
- [ ] Вручную подтверждён ненулевой код тестовой команды при временном нарушении HTTP-контракта или запуске неисправного backend; временные изменения полностью отменены и не коммитятся. Отдельные новые автоматические тесты, browser automation и coverage gates не добавлены.

## Команды проверки

| Команда | Ожидаемый результат |
| --- | --- |
| `mise run test` | Сборка и smoke завершаются кодом 0 без предварительно запущенных серверов. |
| `mise run test` повторно | Код 0; предыдущий запуск освободил процессы и порты. |
| `mise run test` при временном нарушении контракта | Ненулевой код за ограниченное время, понятная диагностика и закрытые процессы; после восстановления снова код 0. |
| `mise run typecheck` | Типы приложения, теста и TS-конфигураций проверены. |
| `git diff --check` | Нет ошибок whitespace. |

В Answer записать коды успешного и неуспешного запусков, а также подтверждение завершения дочерних процессов. Проверки выполняются только при будущей реализации.

## Comments

- Это согласованная граница smoke-теста: публичный HTTP обоих реально запущенных процессов. Компонентные и доменные тесты на этом этапе не нужны.
