# 05: Подготовить новый клон, локальные хуки и инструкции

**Status:** ready-for-agent
**Blocked by:** 04
**What to build:** новый участник следует короткой инструкции, подготавливает клон одной командой, запускает приложение и проверки; локальный pre-commit применяет те же проверки качества.
**Спецификация:** [Каркас приложения](../spec.md#verification-commands).
**Критерии спецификации:** AC-01, AC-09, AC-11–AC-16.

Плановая задача. В рамках текущего запроса её не выполнять.

## Критерии завершения

- [ ] hk настроен на read-only pre-commit с общими задачами линтера и форматирования. Он не исправляет файлы, не добавляет их в индекс и не создаёт коммиты. Импорты конфигурации соответствуют точной версии hk; отдельный Pkl CLI не установлен.
- [ ] hooks:install устанавливает hk только для текущего клона через mise. setup после npm ci вызывает установку хуков; глобальная Git-конфигурация не меняется.
- [ ] check дополнен hk validate и теперь включает полный набор из спецификации. Все проверки по-прежнему работают без установленного локального hook; в CI установка хуков не нужна.
- [ ] Ручной вызов pre-commit на исправном дереве проходит, а на временном нарушении линтера или форматирования возвращает ненулевой код. Рабочее дерево и индекс не переписываются; для проверки не требуется настоящий commit.
- [ ] Корневые инструкции агента содержат dev, test, lint, check и правило Conventional Commits. Существующие правила проекта сохранены; личные предпочтения пользователя в общие документы не перенесены.
- [ ] README содержит фактический стек и версии, короткую подготовку чистого клона, dev и отдельные команды, адреса, HOST/PORT, остановку, сборку, тесты, линтер, все проверки и хуки. Сценарии владельца календаря и гостя и сведения Hexlet сохранены.
- [ ] Полный путь подготовки воспроизведён в чистом клоне либо чистой временной Git-копии без зависимостей и результатов сборки на macOS arm64; lockfiles не переписаны. Linux x64 подтверждается в задаче 06. Не созданы bootstrap framework и дополнительные команды сверх необходимого.
- [ ] Защищённый workflow Hexlet остался побайтово прежним после setup, format и проверки hook. Новые автоматические тесты не добавлены.

## Команды проверки

| Команда | Ожидаемый результат |
| --- | --- |
| `mise install --locked` и `mise run setup` | Чистая копия готова; npm ci не переписал lockfile; hook установлен локально. |
| `mise exec -- hk validate` | Конфигурация hk корректна. |
| `mise exec -- hk run pre-commit` | Код 0 для исправного дерева и ненулевой код при временном нарушении; без настоящего commit. |
| `mise run hooks:install` | Повторная локальная установка не меняет глобальные настройки. |
| `mise run dev` | Оба приложения работают согласно README; Ctrl+C завершает процессы. |
| `mise run test` и `mise run lint` | Документированные отдельные команды работают. |
| `mise run check` | Полный согласованный набор, включая hk validate, проходит. |
| `git diff --check` | Нет ошибок whitespace. |

До и после ручного запуска hook сравнить рабочее дерево, индекс и глобальную Git-конфигурацию. В Answer записать результат подготовки чистой копии и проверок. Команды предназначены для будущей реализации; commit и push не выполнять без отдельного разрешения.

## Comments

- Проверки hook выполняются ручным вызовом hk, без создания тестового коммита. Инструкции отражают работающие команды из предыдущих задач.
