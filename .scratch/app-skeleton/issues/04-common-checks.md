# 04: Запускать проверки качества и smoke одной командой

**Status:** ready-for-agent
**Blocked by:** 03
**What to build:** разработчик одной командой проверяет качество и работоспособность каркаса, а отдельными командами находит и исправляет проблемы форматирования, линтера и типов.
**Спецификация:** [Каркас приложения](../spec.md#verification-commands).
**Критерии спецификации:** AC-08, AC-09, AC-11; локальная часть AC-10.

Плановая задача. В рамках текущего запроса её не выполнять.

## Критерии завершения

- [ ] ESLint flat config с recommended-правилами JavaScript и typescript-eslint проверяет обе части, тесты и применимую конфигурацию. Browser и Node globals разделены; предупреждения приводят к ненулевому коду.
- [ ] Есть отдельные lint, format:check, format и typecheck. Prettier не конфликтует с ESLint; результаты сборки и зависимости исключены. Предоставленный workflow Hexlet исключён из форматирования и автоисправлений до первого запуска format.
- [ ] mise run check использует общие задачи проверки версий, lint, format:check, typecheck, build и smoke. Сборка завершается до smoke и не повторяется внутри одного запуска. В задаче 05 сюда добавляется проверка готовой конфигурации hk; временная пустая конфигурация не создаётся.
- [ ] В исправном состоянии check возвращает код 0; при нарушении любого обязательного шага возвращает ненулевой код. Проверки не исправляют отслеживаемые файлы и не переписывают lockfiles; установленный Git-hook для запуска не нужен.
- [ ] Для линтера, форматирования, типов и smoke локально вручную подтверждены ненулевые коды, включая распространение ошибки через check. Результаты записаны в Answer; временные нарушения отменены. Проверку smoke из задачи 03 можно использовать повторно, если соответствующий код с тех пор не менялся.
- [ ] Команды описаны кратко и доступны из корня. Специальные тесты конфигурационных объектов, второй task runner и дополнительные инфраструктурные сервисы не добавлены.

## Команды проверки

| Команда | Ожидаемый результат |
| --- | --- |
| `mise run lint` | Код 0 в исправном состоянии; ненулевой при временном нарушении правила. |
| `mise run format:check` | Код 0 в исправном состоянии; ненулевой при временном нарушении форматирования. |
| `mise run format` | Исправляет форматирование разрешённых файлов; защищённый workflow остаётся прежним. |
| `mise run typecheck` | Код 0 в исправном состоянии; ненулевой при временной ошибке типов. |
| `mise run check` | Все текущие проверки, сборка и smoke проходят; ошибка каждого шага не теряется. |
| `git diff --check` | Нет ошибок whitespace после отмены временных нарушений. |

Перед и после check сравнить отслеживаемые файлы и lockfiles; допустимы только игнорируемые результаты сборки. В Answer сохранить коды отказов и результат сравнения защищённого workflow. Все команды относятся к будущей реализации.

## Comments

- Локальные подтверждения отказов используются при AC-10; специально падать в GitHub Actions не требуется.
