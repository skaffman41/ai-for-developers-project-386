# 04: Запускать проверки качества и smoke одной командой

**Status:** resolved
**Blocked by:** 03
**What to build:** разработчик одной командой проверяет качество и работоспособность каркаса, а отдельными командами находит и исправляет проблемы форматирования, линтера и типов.
**Спецификация:** [Каркас приложения](../spec.md#verification-commands).
**Критерии спецификации:** AC-08, AC-09, AC-11; локальная часть AC-10.

Запуск: `$implement 04-common-checks` после завершения зависимостей. Порядок выполнения и границы разрешения — в [development workflow](../../../docs/agents/development-workflow.md).

## Критерии завершения

- [x] ESLint flat config с recommended-правилами JavaScript и typescript-eslint проверяет обе части, тесты и применимую конфигурацию. Browser и Node globals разделены; предупреждения приводят к ненулевому коду.
- [x] Есть отдельные lint, format:check, format и typecheck. Prettier не конфликтует с ESLint; результаты сборки и зависимости исключены. Предоставленный workflow Hexlet исключён из форматирования и автоисправлений до первого запуска format.
- [x] mise run check использует общие задачи проверки версий, lint, format:check, typecheck, build и smoke. Сборка завершается до smoke и не повторяется внутри одного запуска. В задаче 05 сюда добавляется проверка готовой конфигурации hk; временная пустая конфигурация не создаётся.
- [x] В исправном состоянии check возвращает код 0; при нарушении любого обязательного шага возвращает ненулевой код. Проверки не исправляют отслеживаемые файлы и не переписывают lockfiles; установленный Git-hook для запуска не нужен.
- [x] Для линтера, форматирования, типов и smoke локально вручную подтверждены ненулевые коды, включая распространение ошибки через check. Результаты записаны в Answer; временные нарушения отменены. Проверку smoke из задачи 03 можно использовать повторно, если соответствующий код с тех пор не менялся.
- [x] Команды описаны кратко и доступны из корня. Специальные тесты конфигурационных объектов, второй task runner и дополнительные инфраструктурные сервисы не добавлены.

## Команды проверки

| Команда                 | Ожидаемый результат                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------- |
| `mise run lint`         | Код 0 в исправном состоянии; ненулевой при временном нарушении правила.             |
| `mise run format:check` | Код 0 в исправном состоянии; ненулевой при временном нарушении форматирования.      |
| `mise run format`       | Исправляет форматирование разрешённых файлов; защищённый workflow остаётся прежним. |
| `mise run typecheck`    | Код 0 в исправном состоянии; ненулевой при временной ошибке типов.                  |
| `mise run check`        | Все текущие проверки, сборка и smoke проходят; ошибка каждого шага не теряется.     |
| `git diff --check`      | Нет ошибок whitespace после отмены временных нарушений.                             |

Перед и после check сравнить отслеживаемые файлы и lockfiles; допустимы только игнорируемые результаты сборки. В Answer сохранить коды отказов и результат сравнения защищённого workflow. Команды выполняются в цикле этой задачи.

## Answer

Выполнено **2026-11-07**, macOS arm64. Все критерии задачи 04 подтверждены; статус `resolved`.

- `eslint.config.mjs` использует flat config, recommended JavaScript и typescript-eslint, отдельные browser globals для frontend/src и Node globals для backend, тестов, скриптов и конфигурации. `eslint-config-prettier/flat` подключён последним. ESLint проверяет 10 исходных и конфигурационных файлов, включая собственный конфиг; зависимости, dist и coverage исключены. Предупреждения отклоняются через `--max-warnings 0`.
- Добавлены npm scripts и общие mise-задачи `lint`, `format:check`, `format`. Prettier проверяет весь репозиторий; ранее существовавшие Markdown-таблицы приведены к его формату без изменения требований. До первого `format` созданы исключения для workflow Hexlet, результатов сборки, зависимостей и lockfiles.
- `check` зависит от общих `env:check`, `lint`, `format:check`, `typecheck`, `test`; существующая зависимость `test → build → env:check` обеспечивает одну сборку обеих частей перед smoke. `mise tasks deps check` и журнал успешного запуска подтверждают этот порядок. Конфигурация hk и её проверка относятся к задаче 05; временный hk.pkl не создавался.
- `tsconfig.tools.json` включает новый ESLint-конфиг; остальные исходники, тесты и конфигурации уже охвачены существующим typecheck. Команды и их поведение описаны в README.
