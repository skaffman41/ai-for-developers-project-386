# 02: Запустить воспроизводимый frontend и backend

**Status:** ready-for-agent
**Blocked by:** 01
**What to build:** разработчик подготавливает окружение из корня, запускает обе части одной командой, открывает страницу каркаса и получает успешный ответ backend; обе части также собираются и запускаются после сборки.
**Спецификация:** [Каркас приложения](../spec.md).
**Критерии спецификации:** AC-01–AC-05, AC-11, AC-12, AC-16–AC-18.

Запуск: `$implement 02-run-application` после завершения зависимостей. Порядок выполнения и границы разрешения — в [development workflow](../../../docs/agents/development-workflow.md).

## Критерии завершения

- [ ] Использован проверенный набор из Answer задачи 01. Приватные frontend и backend объединены npm workspaces с одним корневым lockfile; все внешние прямые зависимости, включая инструменты следующих задач, указаны точными версиями.
- [ ] До первой фактической установки выполнен успешный npm dry-run полного набора с включёнными engine-strict и strict-peer-deps и без lifecycle scripts. Результат записан в Answer. При конфликте набор корректируется и повторно проверяется до установки; force и legacy-peer-deps не используются.
- [ ] Node и hk зафиксированы через mise, mise lockfile поддерживает macOS arm64 и Linux x64. Версия mise описана в короткой инструкции подготовки; проверка окружения отклоняет несовпадение ожидаемых mise, Node и npm.
- [ ] После первой установки создан общий npm lockfile; повторный npm ci проходит без его изменения. Генерируемые результаты, зависимости и локальные env-файлы игнорируются Git.
- [ ] mise run dev запускает страницу «Календарь звонков» с подписью «Каркас приложения» и backend с GET /health: HTTP 200, JSON с единственным полем status со значением ok. Страница проверена в браузере; запуск не требует секретов, БД и внешних сервисов.
- [ ] Работают отдельные dev-команды, HOST/PORT backend и значения по умолчанию из спецификации. Занятый явно выбранный порт даёт ошибку; Ctrl+C общего запуска и ошибка старта одной части завершают принадлежащие ему процессы.
- [ ] mise run build собирает обе части; start:backend и preview:frontend запускают результаты сборки. Строгая проверка типов работает для обеих частей; настройки ESM и запуска TypeScript соответствуют спецификации.
- [ ] Краткая инструкция подготовки и запуска позволяет проверить этот результат. В этой задаче setup готовит npm-зависимости; установка hk-hook подключается в задаче 05, когда появятся его проверки.
- [ ] Предоставленный workflow Hexlet сохранён побайтово. Дополнительная инфраструктура и бизнес-логика бронирований не созданы; автоматический smoke добавляется в задаче 03.

## Команды проверки

Выполняются при будущей реализации, после проверки метаданных. Locked-установка инструментов предполагает подготовленный mise lockfile.

| Команда | Ожидаемый результат |
| --- | --- |
| `mise --version` | Согласованная точная версия mise. |
| `mise install --locked` | Инструменты из lockfile для текущей платформы. |
| `mise exec -- node --version` и `mise exec -- npm --version` | Согласованные Node и npm. |
| `mise exec -- npm install --dry-run --ignore-scripts --package-lock=false --strict-peer-deps --engine-strict --no-audit --no-fund` | Успешное разрешение полного дерева до первой установки; npm-пакеты не устанавливаются. |
| `mise exec -- npm ci` | После создания lockfile установка воспроизводится и не переписывает его. |
| `mise run setup` | Окружение и зависимости готовы; hook пока не устанавливается. |
| `mise run dev` | Обе части запущены; после Ctrl+C порты свободны. |
| `curl --fail --silent --show-error http://127.0.0.1:3000/health` | JSON-контракт; вручную дополнительно сверить HTTP 200 и Content-Type. |
| `mise run dev:frontend` и `mise run dev:backend` | Проверить по отдельности, затем остановить; повторить при занятом порте и проверить ненулевой код. |
| `mise run typecheck` и `mise run build` | Код 0, свежие сборки обеих частей. |
| `mise run start:backend` и `mise run preview:frontend` | Проверить по отдельности после build; затем остановить. |
| `git diff --check` | Нет ошибок whitespace. |

В Answer приложить результат ручной проверки страницы, запуска, остановки и неизменности защищённого workflow. Команда запуска тикета разрешает предусмотренные сборку, установку и отдельный коммит результата; push требует явного разрешения.
