## Команды проверки

Локально при реализации:

| Команда              | Ожидаемый результат                                            |
| -------------------- | -------------------------------------------------------------- |
| `mise run check`     | Полный набор проверок завершается кодом 0.                     |
| `git diff --check`   | Нет ошибок whitespace в подготовленных изменениях.             |
| `git rev-parse HEAD` | Опорный SHA для сопоставления с удалённым запуском после push. |

В workflow обязательна последовательность `mise install --locked` → `mise exec -- npm ci` → `mise run check` после установки зафиксированного mise. Если официальный action уже выполнил locked-установку инструментов, отдельный повторяющий её шаг не нужен.

После отдельно разрешённого или выполненного пользователем push, если gh уже доступен:

- `gh run list --workflow app-check.yml --limit 5 --json databaseId,headSha,status,conclusion,url` — найти запуск для нужного SHA.
- `gh run view RUN_ID --json headSha,status,conclusion,url` — подставить найденный идентификатор и подтвердить completed/success.

При отсутствии gh использовать страницу GitHub Actions; устанавливать дополнительный CLI только ради этой проверки не требуется. Команда запуска тикета разрешает подготовить и локально закоммитить workflow. Если для удалённой проверки нужен commit до завершения всех критериев, явно обозначить его как промежуточный и оставить задачу незавершённой. Push требует отдельного разрешения; затем сопоставить успешный run с фактически отправленным SHA.
