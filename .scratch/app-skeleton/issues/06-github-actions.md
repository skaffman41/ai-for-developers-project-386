# 06: Запускать общий check в GitHub Actions на каждый push

**Status:** ready-for-agent
**Blocked by:** 05
**What to build:** сопровождающий видит успешный запуск полного набора проверок приложения в GitHub Actions после push; предоставленная проверка Hexlet продолжает работать отдельно.
**Спецификация:** [Каркас приложения](../spec.md#acceptance-criteria).
**Критерии спецификации:** AC-01 для Linux x64, AC-09–AC-12; итоговая сверка AC-01–AC-18.

Запуск: `$implement 06-github-actions` после завершения зависимостей. Порядок выполнения и границы разрешения — в [development workflow](../../../docs/agents/development-workflow.md).

## Критерии завершения

- [ ] Создан один дополнительный app-check workflow для push любых веток и тегов, без path-фильтров. Ubuntu 24.04, один job и минимальный набор шагов; CI-матрицы и дополнительные сервисы не добавлены.
- [ ] Используются checkout и официальный mise-action, закреплённые полными commit SHA с комментариями версий; существование SHA и совместимость action проверены по официальным источникам при реализации. Версия mise фиксирована явно; инструменты устанавливаются locked, npm-зависимости — через npm ci.
- [ ] После подготовки запускается тот же mise run check, который проверен локально. Конфигурация не копирует команды отдельных проверок и не устанавливает Git-хуки; секреты Hexlet не нужны.
- [ ] Предоставленный workflow Hexlet побайтово совпадает с исходным; его имя, расположение и действия не менялись. Он исключён из всех исправлений форматирования.
- [ ] Локальный полный check проходит; в Answer задач 03 и 04 есть подтверждения ненулевых кодов обязательных проверок при нарушениях. Искусственно падающий CI-запуск не проводится.
- [ ] После отдельно разрешённого или выполненного пользователем push получен успешный app-check run для соответствующего commit SHA. В Answer записаны URL, SHA и результат; этим подтверждается чистая установка и полный check на Linux x64.
- [ ] Пока push не разрешён или успешный удалённый запуск не наблюдался, удалённая часть AC-10 остаётся неподтверждённой и задача не получает resolved. Готовность файла workflow не считается свидетельством успешного Actions.
- [ ] Итоговая сверка всех критериев спецификации записана в Answer; отсутствуют бизнес-логика бронирований и дополнительная инфраструктура.

## Команды проверки

Локально при реализации:

| Команда | Ожидаемый результат |
| --- | --- |
| `mise run check` | Полный набор проверок завершается кодом 0. |
| `git diff --check` | Нет ошибок whitespace в подготовленных изменениях. |
| `git rev-parse HEAD` | Опорный SHA для сопоставления с удалённым запуском после push. |

В workflow обязательна последовательность `mise install --locked` → `mise exec -- npm ci` → `mise run check` после установки зафиксированного mise. Если официальный action уже выполнил locked-установку инструментов, отдельный повторяющий её шаг не нужен.

После отдельно разрешённого или выполненного пользователем push, если gh уже доступен:

- `gh run list --workflow app-check.yml --limit 5 --json databaseId,headSha,status,conclusion,url` — найти запуск для нужного SHA.
- `gh run view RUN_ID --json headSha,status,conclusion,url` — подставить найденный идентификатор и подтвердить completed/success.

При отсутствии gh использовать страницу GitHub Actions; устанавливать дополнительный CLI только ради этой проверки не требуется. Команда запуска тикета разрешает подготовить и локально закоммитить workflow. Если для удалённой проверки нужен commit до завершения всех критериев, явно обозначить его как промежуточный и оставить задачу незавершённой. Push требует отдельного разрешения; затем сопоставить успешный run с фактически отправленным SHA.
