## Parent

[Основная запись на встречу: типы, бронирование и раздел владельца календаря](https://github.com/skaffman41/ai-for-developers-project-386/issues/37).

## What to build

Владелец календаря открывает `/owner` с двумя вкладками и видит предстоящие/текущие, прошедшие или все сохранённые бронирования. Обновление независимых списков сохраняет работу формы, а сбой ясно показывает актуальность оставшихся данных.

## Acceptance criteria

- [ ] `GET /api/owner/bookings` проходит всю контрактную/runtime-цепочку. period по умолчанию upcoming; upcoming включает окончание строго позже серверного сейчас и сортирует по возрастанию начала, past — окончание уже наступило, последние первыми, all — вся история по возрастанию начала. Списки без пагинации, пустой массив успешен, неверный период/лишние поля отклоняются.
- [ ] `/owner` по умолчанию показывает «Бронирования», рядом «Типы встреч». Запись содержит тип/длительность, дату/полный интервал, имя/email, Europe/Moscow; различимы предстоящая, текущая и завершившаяся встречи. Горизонт гостя не удаляет историю.
- [ ] Загрузки при открытии и по «Обновить», без периодического опроса. Ошибка одного списка не блокирует другой. Первая загрузка имеет индикатор/ошибку/повтор; при обновлении прежние данные видимы, при сбое помечены устаревшими. Видно время последней успешной загрузки. Пустые состояния «нет типов» и «типы есть, нет бронирований» различаются и предлагают подходящее действие.
- [ ] Обновление списка/переключение вкладки сохраняет ввод и не прерывает известную либо неизвестную отправку создания типа; прежняя отправка сохраняет свои ключ/данные и блокировку. Новый тип не исчезает из-за запоздавшего ответа обновления.
- [ ] HTTP с SQLite проверяет все периоды и порядок, московские даты, момент начала/окончания на управляемых часах и историю за горизонтом. Playwright с настоящим backend проверяет вкладки, данные, независимые ошибки/повторы/устаревание, обновление одновременно с созданием и сохранение полей.
- [ ] Клавиатура, семантика объявлений, фокус, названия и ширины 320/1440 px соблюдены; полный check успешен.

## Testing Decisions

T2, T3, T5, T7, T8; вклад в AC1, AC3, AC8, AC10–AC11. Подготовленные бронирования позволяют независимо проверить чтение до готовности POST. Поэтому подтверждение гостя не является блокером; сквозное сопоставление созданной им записи владельцу относится к финальной приёмке.
