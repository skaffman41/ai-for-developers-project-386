## What to build

Гость после выбора типа явно переходит к дате и выбирает полный свободный интервал по московским правилам. На отсутствие подходящего времени, загрузку и сбои есть понятные состояния и повтор. Настоящая доступность учитывает сохранённые бронирования всех типов, а не только список начал.

## Acceptance criteria

- [ ] `GET /api/availability` проходит единую цепочку контракта/генерации/runtime-проверки. Возвращаются eventTypeId, date, timeZone, firstDate, lastDate, asOf и slots; отсутствие date означает серверное московское сегодня. UTC-моменты имеют Z. Несуществующий тип, невозможная/некорректная дата и выход за горизонт дают согласованные ошибки; неизвестные параметры не удаляются молча.
- [ ] Сегодня и следующие 13 московских дней; будни 09:00–18:00; начала через 30 минут от 09:00, строго позже серверного сейчас. Окончание вычисляется по длительности и не позже 18:00. Учитывается полный интервал и занятость всех типов; соприкасающиеся границы допустимы. Длительность не округляется, чтение не резервирует время.
- [ ] Схема хранения бронирований и её поддерживаемое изменение введены в объёме, необходимом для чтения занятости. Результат проверяется на реальных данных SQLite; данные для ещё не реализованной операции создания готовит изолированная проверочная среда. Отдельной сохраняемой сущности слота нет.
- [ ] Выбор типа открывает второй шаг по явному действию. Календарь использует серверные границы, выходные недоступны; слоты показаны начало–окончание. Смена типа/даты сбрасывает зависимый слот, простой возврат сам по себе выбор не сбрасывает. При выборе/возврате к дате доступность запрашивается заново, прежние слоты скрыты и продолжение заблокировано до загрузки.
- [ ] Есть отсутствие слотов с выбором другой даты/типа, загрузка, ошибка и повтор. Московское отображение не зависит от часов/часового пояса браузера; устаревший список не предлагается для новой записи. Шаг контактов добавляется следующим срезом.
- [ ] Введены управляемые серверные часы проверочного окружения без служебных HTTP-маршрутов. HTTP покрывает полночь, границы горизонта/расписания, выходные, невозможные даты, начало ровно сейчас, 45 минут и крайние 1/540, пересечения разных типов и соприкосновение. Playwright с настоящим backend проверяет выбор, возврат/обновление, отсутствие слотов, ошибки и другой часовой пояс браузера.
- [ ] Клавиатура, доступные названия и отсутствие переполнения на 320/1440 px применены к новым элементам; генерация/типы и полный check успешны.

## Testing Decisions

T2, T3, T5–T8; вклад в AC2, AC8–AC11. Создание типа не является блокером: этот сценарий самостоятельно проверяем с подготовленными типами, в том числе до появления формы владельца.
