[Основная запись на встречу: типы, бронирование и раздел владельца календаря](https://github.com/skaffman41/ai-for-developers-project-386/issues/37).

## What to build

Гость открывает `/booking` и получает реальный список типов встреч из постоянной SQLite через весь общий контракт. На новой пустой БД показано понятное отсутствие типов с обновлением; для существующих типов видны название, длительность и описание. Это первый небольшой законченный результат: OpenAPI → производные схемы и типы → ручной Fastify-обработчик с проверкой ответа → сгенерированный клиент → проверка входящего ответа → React. Первая вертикаль реализует чтение, дальнейшие шаги записи добавляются следующими срезами.

## Acceptance criteria

- [ ] В единственном прямом OpenAPI 3.1 описаны работающий `GET /api/event-types` и сохранённый `/health`. Закреплённая согласованная цепочка генерирует клиент, общие модели/схемы, серверные типы и документацию. Будущие операции добавляются вместе со своими срезами; неработающие маршруты не объявляются реализованными.
- [ ] Серверные запросы и ответы, а также входящие клиентские ответы проверяются через Ajv2020 по производным схемам; нет независимых ручных контрактов и импорта браузерного SDK в backend. Неизвестные поля/неверные типы не исправляются автоматически. Невалидный ответ не отображается как корректные данные.
- [ ] Чтение работает с реальной файловой SQLite. Введены минимальная схема типов с версией, явная подготовка пустой БД и документированный постоянный путь. Обычный запуск не создаёт замену отсутствующей БД; проверяет принятые настройки SQLite и останавливается до HTTP при недоступном/повреждённом файле или чужой/неподдерживаемой схеме. Подготовка/поддерживаемые изменения схемы транзакционны. Демоданных в продукте нет.
- [ ] Список возвращает нормализованные данные, устойчивые различимые обозначения и определённый порядок новых типов первыми, в том числе при совпадениях названия/времени создания. Пустой список — успешный ответ. Заполнение непустого списка в этом срезе выполняет только проверочная подготовка, а не служебный HTTP-маршрут.
- [ ] В гостевом UI есть загрузка, непустой/пустой список, ошибка и повтор. Сохраняются главная, прямое открытие `/booking`, reload и история. Доступные названия, видимый фокус и узкий вид применяются сразу к введённым элементам.
- [ ] Vitest проверяет реальные HTTP-ответы с временной файловой БД, пустой и наполненный список и отказ запуска на проблемной БД. Playwright запускает настоящий backend и проверяет показ типов/пустого состояния и непригодный ответ. Процессы и данные изолированы и освобождаются.
- [ ] С первого среза общий `mise run check` включает валидацию источника OpenAPI, повторную генерацию без расхождений, компиляцию общих/серверных/клиентских типов и новые проверки. Существующий smoke и полезные браузерные сценарии сохранены, ожидания заглушки обновлены.

## Testing Decisions

Реализует соответствующую часть T1, T2, T6, T7 и T8 родителя; вклад в AC3, AC8–AC11. Самопроверка сгенерированных типов не заменяет реальный HTTP и браузер. Полный check и необходимые Standards/Spec review обязательны по workflow.
