## What to build

Рецензент получает воспроизводимое доказательство, что существующий HTTP-тест обнаруживает ошибочное разрешение частичного пересечения встреч разных типов и проходит после восстановления правильного правила.

## Acceptance criteria

- [ ] Эксперимент выполнен в отдельной рабочей копии на зафиксированном commit с изолированной файловой SQLite и существующим HTTP-тестом частичного пересечения разных типов.
- [ ] После подготовки сборки временное минимальное изменение разрешает запрещённое частичное пересечение. Тест concurrent overlapping types have one winner, exact concurrent retries and touching boundaries падает именно на ожидании одного 201 и одного 409 для интервалов 06:00–06:45 и 06:30–07:00 UTC. Ошибка сборки или окружения не считается красным результатом.
- [ ] После восстановления правильной реализации и соответствующей сборки та же команда целевого запуска проходит. Сломанная реализация отсутствует в результате, истории интеграционной ветки и публикациях.
- [ ] В тикете сохранены правило, название теста, проверенный SHA, минимальное временное изменение, точные команды, коды завершения, красный и зелёный результаты, причина падения и журналы. В проекте сохранён краткий отчёт со ссылкой на доказательства.
- [ ] На восстановленной реализации проходит существующий mise run check; git diff --check успешен. При нечувствительном существующем тесте критерий остаётся невыполненным и запрашивается отдельное решение пользователя, новый тест автоматически не добавляется.

## Testing Decisions

Спецификация T3, T4, T6, T7. Использовать точный целевой запуск из спецификации после сборки; не добавлять тесты или инфраструктуру мутационного тестирования. Миграция исходного формата контракта не является зависимостью эксперимента, поскольку серверное правило и наблюдаемый HTTP-результат сохраняются.
