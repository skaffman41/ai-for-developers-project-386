## Parent

[Спецификация #55 — Шаг 7: Docker и бесплатный публичный стенд на Railway](https://github.com/skaffman41/ai-for-developers-project-386/issues/55).

## What to build

Проверяющий открывает публичную ссылку на бесплатный учебный календарь, владелец создаёт тип встречи, гость бронирует слот с вымышленными контактами, а владелец видит результат. Другой гость не может подтвердить пересекающуюся встречу. Сопровождающий видит воспроизводимую ручную выкладку через MCP и отчёт о выполнении всех критериев шага 7.

После подготовки контейнера и MCP опубликовать согласованную версию из основной ветки на Railway в пределах бесплатных Free/Trial-кредитов и выполнить итоговую внешнюю приёмку. В репозитории остаются публичная ссылка, безопасные инструкции и точное описание ограничений бесплатного стенда.

## Acceptance criteria

- [ ] Обе блокирующие задачи приняты; выбранная версия контейнерной реализации и конфигурации включена в основную ветку после отдельно разрешённой публикации кода и интеграции. Проверен конкретный исходный commit для выкладки.
- [ ] По явной команде через официальный MCP создан и опубликован Docker-сервис Railway в пределах подтверждённых бесплатных Free/Trial-кредитов с бюджетом 0 ₽, без постоянного диска, внешней платной БД и других платных ресурсов. В отчёте сохранены результат MCP-операции и связь сервиса с проверенной версией исходников и образом.
- [ ] Автоматическая выкладка приложения отключена; изменения конфигурации применяются только в пределах явно разрешённой выкладки. Описанный маршрут ручного обновления соответствует фактической конфигурации.
- [ ] По публичному адресу приложение отвечает на выданном PORT; работают `/health`, frontend и ресурсы, прямое открытие и обновление `/booking` и `/owner`, контрактный API.
- [ ] На публичном сервисе проходит сценарий «создать тип встречи → забронировать будущий свободный слот с вымышленными контактами → увидеть бронирование у владельца календаря» с настоящим backend и SQLite.
- [ ] Две разные попытки на пересекающиеся полные интервалы дают один успех и контрактный отказ «Слот уже занят» второй попытке, без второго бронирования. Повтор той же попытки проверяется отдельно и сохраняет прежний результат в пределах текущей БД.
- [ ] Подтверждено пустое состояние нового контейнера из проверенного образа, соответствующего выбранному исходному commit, без постоянного тома. Локальные проверки постоянного хранилища и непригодной БД связаны с тем же принятым результатом; если после них менялись затронутые исходники или окружение, применимые проверки повторены.
- [ ] README содержит действующую публичную ссылку, воспроизводимые сборку и запуск, инструкции MCP-авторизации и ручного обновления, работу с локальным постоянным хранилищем и ограничения выбранных Free/Trial-кредитов Railway. Явно описаны вымышленные данные, открытый раздел владельца, допустимый сброс SQLite при замене контейнера, отсутствие обещания долговечности без тома, квоты и возможная задержка пробуждения, если засыпание включено.
- [ ] Реальные секреты, OAuth-сессии и локальная рабочая БД отсутствуют в публикуемых настройках и образе. Проверена история репозитория; результат сохранён без раскрытия чувствительных значений. При выявлении реального секрета критерий не считается выполненным; переписывание истории без отдельного разрешения не производится.
- [ ] На итоговом результате проходит существующий полный `mise run check`. Новых тестов нет, защищённый workflow Hexlet сохранён. Содержательные изменения прошли необходимое независимое ревью Standards и Spec по workflow проекта.
- [ ] Отчёт сопоставляет все AC1–AC14 и T1–T9 спецификации #55 с доказательствами: commit, идентификатор образа, команды и коды завершения, URL, время публичной проверки, результат гостя и владельца календаря, отказ пересечения и фактические настройки бесплатного ручного деплоя.
- [ ] Локальная готовность, состоявшийся деплой и результат публичной приёмки различаются явно. Непройденный критерий, отсутствие авторизации или нужной MCP-возможности остаются конкретной блокировкой; успех локальных проверок не выдаётся за публичную готовность.

## Testing Decisions

Применяются все T1–T9 спецификации #55 с акцентом на T7–T9. Существующий полный прогон подтверждает регрессии, а публичная приёмка выполняется разово снаружи через браузер и HTTP на реально доступных будущих слотах. Разные попытки бронирования используют разные ключи, повтор одной попытки — тот же ключ. Локальные Playwright fixtures с фиксированными часами не объявляются прогоном против Railway. Принятые доказательства блокеров переиспользуются только при совпадающем проверенном результате и применимом окружении; изменения требуют затронутой повторной проверки. Новые тестовые случаи и инфраструктура не добавляются.

## Scope and external prerequisite

Готовность задач в локальной интеграционной ветке позволяет подготовить выкладку, но не разрешает push, PR или merge. Публикация сервиса начинается только после отдельно разрешённого включения нужной версии в основную ветку и явной команды деплоя, как согласовано в #55. При отсутствии этого разрешения сохраняется готовый результат и конкретный внешний блокер; задача не закрывается как выполненная.

Принятие результата этой задачи не закрывает и не изменяет родительскую спецификацию автоматически и не отмечает шаг завершённым в интерфейсе Hexlet.
