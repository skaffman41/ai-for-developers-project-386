# Единый сервис для публичного учебного стенда

Публичная версия первого проекта предназначена для учебной демонстрации и проверки сценариев гостя и владельца календаря с вымышленными именами и email. Бюджет размещения стенда — 0 ₽. Раздел владельца календаря сохраняет предусмотренный проектом доступ без входа: посетителям доступны создание типов встреч и просмотр бронирований, поэтому стенд рассчитан на вымышленные данные.

Frontend и API публикуются по одному адресу из одного контейнера: один процесс Fastify раздаёт собранный frontend и обслуживает API. Прямое открытие и обновление `/booking` и `/owner` возвращают приложение. Единый сервис позволяет обойтись без отдельного процесса раздачи статики и согласования конфигурации двух сервисов; сохраняется один экземпляр backend с SQLite.

Пустая SQLite-база с текущей схемой подготавливается явной командой при сборке Docker-образа и входит в образ. Благодаря этому новый контейнер автоматически запускает приложение без отдельной ручной подготовки БД, с пустыми списками типов встреч и бронирований. Обычный старт открывает подготовленный файл и проверяет его; отсутствующий, недоступный, повреждённый файл или неподдерживаемая схема останавливают запуск, как предусмотрено [ADR 0003](0003-booking-storage.md). При локальном размещении с постоянным файлом БД сохраняется отдельная явная подготовка этого файла.

11 ноября 2026 года по прямой команде пользователя вместо Render выбран Railway MCP — предусмотренный заданием Hexlet запасной вариант, когда Render требует оплату или недоступен. При проверке Render форма выбора репозитория потребовала карту; ресурсы не создавались. Архитектура Docker и критерии пользовательского сценария сохранены.

Размещение использует только бесплатные Free/Trial-кредиты Railway в пределах бюджета 0 ₽, без постоянного тома и внешней БД. Фактический тариф, доступный лимит и ограничения аккаунта проверяются до создания сервиса; платное повышение не разрешено. Railway предоставляет новым аккаунтам Trial до 30 дней с $5, затем Free с $1 в месяц; эти условия не доказывают остаток конкретного аккаунта. Основание — [документация Trial](https://docs.railway.com/pricing/free-trial) и [тарифов](https://docs.railway.com/pricing/plans).

Принимается потеря изменений SQLite при замене контейнера или новом деплое; сохранение после сна или перезапуска без постоянного тома не обещается. Это исключение из гарантий долговечности [ADR 0003](0003-booking-storage.md) только для бесплатного публичного стенда. При локальном постоянном хранилище гарантии сохраняются; атомарность и повторы действуют в пределах текущей БД.

Первоначальная публикация и последующие обновления выполняются через официальный MCP Railway по отдельной команде после включения выбранной версии в `main`. Автодеплой отключён, настройки и отложенные изменения применяются явно в рамках выкладки. Шаблон подключения не содержит секретов и ничего не создаёт сам.

README описывает действительные лимиты Free/Trial, сброс данных и условия сна, если он включён. Ограничения Render «15 минут / около минуты» не используются для Railway. Полные согласованные требования и границы проверок находятся в [плане v2](../plans/step-7-render-free/v2/spec.md); v1 сохраняет историю первоначального решения.
