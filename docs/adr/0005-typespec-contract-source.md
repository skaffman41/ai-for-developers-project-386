# TypeSpec как источник API-контракта

Для завершения [шага 6 проекта Hexlet](https://ru.hexlet.io/projects/386/members/54670?step=6) принимаем TypeSpec единственным исходным описанием HTTP-контракта. Шаг прямо требует TypeSpec, поэтому дополнительный этап генерации оправдан соответствием заданию. Это пересматривает только выбор исходного формата в [ADR 0004](0004-api-contract.md): `contract/openapi.json` становится генерируемым артефактом, из которого существующие инструменты выпускают клиентский SDK, серверные типы и схемы проверки. Остальные решения ADR 0004 сохраняются.

При миграции сохраняем действующие операции, поля, статусы и правила проверки данных. Вся цепочка TypeSpec → OpenAPI → производные артефакты выполняется одной командой `mise run api:generate`; артефакты продолжают храниться в Git, а CI повторяет генерацию и проверяет расхождения, включая новые файлы. Генерируемые пути и запрет ручных правок должны быть явно записаны в `AGENTS.md`.

Решение согласовано 10 ноября 2026 года при разборе готовности к шагу 6. Миграция ещё не выполнена; существующая реализация и неизменяемый снимок `docs/plans/booking-core/v1/` относятся к прежнему исходному формату.
