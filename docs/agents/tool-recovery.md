# Tool Failure Recovery

После технической ошибки сохраняй цель тикета и ищи безопасный рабочий маршрут. Одна ошибка инструмента не доказывает блокировку задачи или ошибку приложения.

## Диагностика

Сохрани команду или операцию, код выхода и конкретную диагностику, исключив секреты и auth-заголовки. Прочитай доступную справку или troubleshooting инструмента. Различай причины:

| Категория    | Признаки                                                       | Следующий шаг                                                                                                                             |
| ------------ | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Инструмент   | Сбой daemon, недоступный MCP, неподдерживаемая операция        | Используй другой уже установленный CLI, официальный API или штатное средство для того же разрешённого действия.                           |
| Сеть         | Ошибка DNS, TCP timeout, TLS, HTTP 401/403/404/429/5xx         | Проверь доступность именно нужного хоста; разделяй DNS, соединение, TLS и HTTP. Проверь влияние proxy-настроек, не раскрывая credentials. |
| Конфигурация | Неверный путь, рабочий каталог, переменная или версия CLI      | Сверь с конфигурацией репозитория и `--help`; исправь локальную причину в разрешённом объёме.                                             |
| Зависимости  | Конфликт engines или peers, отсутствующая публикация           | Сопоставь метаданные точных версий с toolchain; согласуй минимальное изменение с требованиями спецификации до установки.                  |
| Приложение   | Воспроизводимое исключение, неверный HTTP-ответ, падение теста | Исправляй код в границах тикета и повтори применимые проверки. Замена инструмента не должна скрыть дефект.                                |

## Безопасные альтернативы

Предпочитай уже установленные инструменты, официальные API и стандартные библиотеки окружения. Для чтения npm-метаданных после ошибки браузера попробуй `npm view <package>@<version> version engines peerDependencies peerDependenciesMeta dependencies --json` или HTTPS GET официального registry через curl. GitHub release assets доступны через официальный Releases API.

Для сетевого запроса задавай ограниченное время соединения и общее время, например `curl --connect-timeout 5 --max-time 15`. При неисправном необязательном proxy допустим отдельный прямой публичный запрос, если это разрешено политикой доступа. Это не разрешение обходить обязательный корпоративный gateway. Исправление настройки для одного процесса предпочтительнее глобального изменения. Пустые engines, успех HTTP-запроса или работа альтернативного клиента не заменяют проверку требуемых данных и результата приложения.

Не повторяй одинаковую неудачную операцию без новых оснований. Повтор оправдан временным сбоем или исправлением причины; после повторяющейся ошибки меняй способ либо диагноз. Выполняй независимые части задачи, пока восстанавливаешь недоступный маршрут.

Если skill требует остановить конкретный инструмент, останови его и соблюди требование перед его повторным запуском или заменой в том же маршруте. Например, запрет самостоятельно искать другой браузер после ошибки Chrome CLI не мешает прочитать публичный npm registry уже установленным curl. Не распространяй узкое ограничение инструмента на всю задачу.

## Границы и блокировка

- Сохраняй ограничения безопасности, авторизацию и критерии приёмки. Не отключай проверку TLS или обязательные проверки; не используй `force`/`legacy-peer-deps` для сокрытия несовместимости.
- Дополнительные инструменты вне согласованного объёма задачи, изменение глобальной конфигурации и разрушительные операции требуют разрешения. Не устанавливай новый CLI только потому, что один клиент отказал. Подготовка уже согласованных инструментов по явно запущенному тикету подчиняется [development-workflow.md](development-workflow.md).
- Если sandbox блокирует необходимое разрешённое действие, используй штатный механизм разрешений. Отказ доступа не обходи другим каналом; при отклонении автоматическим review сообщи действие и указанную причину.
- Когда разумные альтернативы исчерпаны, сохрани выполненную работу и конкретную блокировку в Answer или Comments: достигнутый результат, невыполненные критерии, команды и ошибки, испробованные альтернативы, точные действия или данные от пользователя для продолжения. Примени незавершённый статус по [triage-labels.md](triage-labels.md).
- `resolved` допустим только после выполнения всех критериев. Отсутствующий доступ, пропущенная обязательная проверка или неподтверждённый удалённый запуск не считаются успехом.
