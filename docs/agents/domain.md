# Domain Docs

Используется single-context: один `GLOSSARY.md` в корне репозитория и архитектурные решения в `docs/adr/`.

## Before exploring

- Если существует корневой `GLOSSARY.md`, прочитай его перед исследованием проекта.
- Если существует `docs/adr/`, прочитай ADR, относящиеся к текущей задаче.
- Если этих файлов нет, продолжай работу без замечаний об их отсутствии и без предложения создать их заранее.

## Create only when needed

Skill `domain-modeling` создаёт глоссарий, когда согласованы реальные доменные термины, и ADR, когда принято архитектурное решение, которое нужно сохранить.

- Термины и определения: `GLOSSARY.md`.
- Решения, причины и последствия: `docs/adr/NNNN-<decision>.md`.

Пустые файлы, каталоги и вымышленные решения заранее не создаются.

## Use the glossary vocabulary

Используй термины глоссария в спецификациях, задачах и предложениях изменений. Если понятие отсутствует, проверь, используется ли оно в проекте; фиксируй определение при его согласовании через `domain-modeling`.

## Flag ADR conflicts

Если предложение противоречит существующему ADR, явно укажи документ и причину пересмотра решения.
