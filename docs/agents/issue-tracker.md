# Issue tracker: Local Markdown

Задачи и спецификации этого репозитория хранятся в `.scratch/`. GitHub Issues и внешние метки не создаются; операции трекера выполняются через локальные файлы.

## Conventions

- Одна фича — один каталог `.scratch/<feature-slug>/`.
- Спецификация: `.scratch/<feature-slug>/spec.md`.
- Задачи реализации: `.scratch/<feature-slug>/issues/<NN>-<slug>.md`, по одному файлу на задачу. Нумерация начинается с `01` внутри фичи; блокирующие задачи идут первыми. Не объединяй все задачи в один файл.
- Статус записывается в начале задачи как `**Status:** <value>`. Роли triage и их значения описаны в [triage-labels.md](triage-labels.md).
- Зависимости записываются как `**Blocked by:** 01, 02` либо `**Blocked by:** None`. Для зависимостей вне текущей фичи указывай относительный путь к файлу задачи.
- Комментарии и история обсуждения дописываются в конец файла под заголовком `## Comments`.
- Каталоги создаются при появлении реальной спецификации или задачи; пустые заготовки не нужны.
- Спецификации и тикеты в `.scratch/` отслеживаются Git. Исключения для локального мусора не должны скрывать Markdown-файлы трекера.

## Resolve a ticket reference

- Полный путь указывает на конкретный тикет. Короткий идентификатор, например `02-run-application`, сопоставляй с точным именем `02-run-application.md` среди `.scratch/*/issues/`. Для поиска используй `rg --files --hidden .scratch -g '02-run-application.md'`.
- При единственном совпадении прочитай весь тикет, включая Comments и Answer, и соответствующий `.scratch/<feature>/spec.md`. Назови заголовок задачи до начала реализации.
- При нескольких совпадениях запроси feature или полный путь; при отсутствии проверь написание и сообщи об отсутствии тикета. Не выбирай похожий тикет и не создавай замену автоматически. Один номер `02` не является глобальным идентификатором.
- Номера в `Blocked by:` разрешай в каталоге `issues/` той же фичи; каждый номер должен соответствовать ровно одному файлу. Путь внешней зависимости разрешай относительно каталога текущего тикета.
- Для каждой зависимости прочитай статус и результат. `needs-info`, `claimed`, `ready-for-agent` и `ready-for-human` означают незавершённость; `wontfix` требует пересмотра зависимой задачи. Если `resolved` противоречит Answer или критериям, сначала разберись с расхождением.

Границы разрешения команды `$implement <id>` и цикл выполнения описаны в [development-workflow.md](development-workflow.md).

## Tracker operations

- **Publish to the issue tracker:** создай спецификацию или отдельные файлы задач по указанной структуре.
- **Fetch the relevant ticket:** прочитай указанный файл целиком, включая комментарии. Номер задачи имеет смысл внутри конкретной фичи; при неоднозначности уточни путь.
- **List issues:** просмотри файлы в `.scratch/*/issues/` и отфильтруй по локальному статусу.
- **Apply a triage role:** обнови поле `Status:` согласно словарю локальных ролей.
- **Comment:** добавь запись в `## Comments`, сохранив предыдущие записи.
- **Close a completed task:** зафиксируй результат и проверку критериев приёмки в `## Answer`, затем установи `Status: resolved`.
- **Reject a task:** запиши причину в `## Comments` и установи `Status: wontfix`.

Для задач реализации `claimed` означает работу в процессе, `resolved` — завершение. Терминальные статусы — `resolved` и `wontfix`; зависимость считается выполненной только при `resolved`. Задачу с отклонённой зависимостью нужно пересмотреть, прежде чем начинать.

## Wayfinding operations

Для `/wayfinder` используются локальная карта и отдельные задачи решений:

- **Map:** `.scratch/<effort>/map.md` с разделами Notes, Decisions so far и Not yet specified по шаблону skill.
- **Child ticket:** `.scratch/<effort>/issues/<NN>-<slug>.md`. Поле `Type:` содержит `research`, `prototype`, `grilling` или `task`; поле `Status:` — `open`, `claimed` или `resolved`. Роли triage к задачам решений не применяются.
- **Blocking:** поле `Blocked by:` перечисляет номера блокирующих задач. Задача доступна, когда все её зависимости имеют статус `resolved`.
- **Frontier:** первая по номеру задача со статусом `open`, у которой выполнены все зависимости.
- **Claim:** установи `Status: claimed` и сохрани файл до начала работы.
- **Resolve:** добавь результат в `## Answer`, установи `Status: resolved`, затем допиши краткий вывод и относительную ссылку на задачу в Decisions so far карты.
