## Содержимое и связи

Каждый импорт содержит полный исходный текст, включая существующие `Answer` и `Comments`, SHA-256 исходных байтов, путь, исходный commit и неизменяемую ссылку `blob/<commit>/<path>`. Спецификация изначально не имела раздела `Answer`; её история сохранена без вымышленного результата. Относительные Markdown-ссылки заменены абсолютными ссылками на файлы того же исходного коммита. Для каждого target проверены существование файла и используемый заголовок. Ссылки на `#answer` ведут на архивный Markdown: якорь заголовка Issue не считается якорем файла.

Native parent для #6–#11 — #5. Native blocking chain: #6 → #7 → #8 → #9 → #10 → #11, где стрелка означает «блокирует». Все семь Issues закрыты с причиной `completed`, поскольку результаты уже входят в исходный commit этапа 2. Открытые Issues текущей реализации #1–#4 этим импортом не закрываются.

[tracker-migration.json](tracker-migration.json) хранит соответствия, database ID, исходные и опубликованные хеши, стабильные маркеры, связи, преобразованные ссылки и итог проверки. Этот manifest описывает миграцию истории; согласованный план новой реализации отдельно хранится в [docs/plans/github-issues-workflow/v1](../plans/github-issues-workflow/v1/spec.md).

## Повторный запуск без дублей

Устойчивый маркер каждого документа имеет точный формат:

```text
<!-- legacy-tracker-migration path=<полный старый путь> commit=6e03736e19494b99ca40a4e64e076145b37b7941 -->
```

Перед **каждым** возможным созданием прочитай все открытые и закрытые Issues целевого репозитория через API `issues?state=all&per_page=100` с `--paginate`, исключая PR. Ищи точный маркер из manifest во всём теле. Единственное совпадение означает существующую запись; повторно её не создавай. Более одного — ошибка данных, требующая разбора. При отсутствии проверь исходный SHA-256 и согласованный объём импорта до создания. После timeout записи сначала перечитай состояние; сам timeout не означает, что запись не произошла.

При повторном запуске сохраняй существующие тела: расхождение ожидаемого хеша требует разбора, а не автоматической перезаписи. Родительские и блокирующие связи проверяй перед добавлением и после записи. Импортированную завершённость проверяй отдельно по `state=closed`, `state_reason=completed` и исходной истории.

## Проверка

Итоговый безопасный повтор в режиме чтения зафиксирован в manifest: создано **0** новых Issues; найдено ровно по одному маркеру для всех семи документов. Через GET API проверены точные тела и их SHA-256, семь состояний `closed/completed`, шесть parent-связей и пять блокирующих рёбер. Исходные семь файлов сравнены побайтово с `git show 6e03736e19494b99ca40a4e64e076145b37b7941:<path>`; архив не изменён.

Отдельно проверены существование всех категорий, triage и `type:*` меток, а также ровно одна категория и одна роль triage у четырёх текущих открытых Issues. Локальные ссылки, форматирование и `git diff --check` проверяются вместе с полным существующим `mise run check`. Новые автоматические тесты для этой миграции не предусмотрены согласованным планом.
